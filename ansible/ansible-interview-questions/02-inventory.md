# 02 — Inventory & Targeting (🟢 7 · 🟡 7 · 🔴 6)

> Course ref: [02-inventory-adhoc.md](../ansible-mastery/02-inventory-adhoc.md)

## 🟢 Basic

**Q1. What is an inventory? What formats does it support?**
> A: The list of managed hosts with grouping and per-host/group variables. INI or YAML (static), plus dynamic sources via inventory plugins or executable scripts.

**Q2. How do you define a group of groups?**
> A: INI: `[prod:children]` listing member groups. YAML: `prod.children: {web: …, db: …}`.

**Q3. What is `ansible_host`?**
> A: A behavior inventory variable giving the real IP/hostname to connect to — lets the logical inventory name (`web1`) differ from the DNS name.

**Q4. How do you run against only some hosts?**
> A: `--limit` with a pattern: group names, unions `web:db`, intersection `web:&prod`, exclusion `web:!canary`, indexes `web[0]`, regex `~web\d+`.

**Q5. What are `group_vars` and `host_vars`?**
> A: Directories (next to the inventory or playbook) of YAML files applied per group or per host — the standard way to attach variables, auto-loaded by name.

**Q6. What does `ansible all -i "host1," -m ping` do — and why the comma?**
> A: Ad-hoc ping against an inline host list; the trailing comma makes it a list literal rather than a filename.

**Q7. How do you see resolved inventory data?**
> A: `ansible-inventory -i inventory --list` (full JSON with vars) or `--graph` (tree). Also `--host <name>` for one host.

## 🟡 Intermediate

**Q8. How do you reach private-subnet hosts through a bastion?**
> A: `ansible_ssh_common_args: '-o ProxyJump=deploy@bastion'` per host/group, or an `ssh_config` block, or run from the bastion with `delegate_to`. Each keeps credentials on your side, target stays private.

**Q9. Playbook-dir `group_vars` vs inventory-dir `group_vars` — which wins?**
> A: Playbook-adjacent wins over inventory-adjacent. General rule: closer to the code = stronger (but still below runtime sources like `set_fact`/`-e`).

**Q10. `command` vs `shell` for ad-hoc ops — when do you accept `shell`?**
> A: Default `command` (no shell parsing, safer). Accept `shell` only when piping/redirect is genuinely needed, quote carefully, and prefer adding `changed_when`/`creates` semantics.

**Q11. A host is in two groups with conflicting scalar vars. What wins?**
> A: More specific beats general: host_vars > group_vars, child group > parent group. Dicts follow `hash_behaviour` (default `replace`, last wins wholesale) — merge explicitly with `combine` if needed.

**Q12. How do `ansible_connection` values change execution?**
> A: `ssh` (default, OpenSSH), `local` (run on controller), `docker`, `podman`, `winrm` (Windows), `network_cli` (switches) — same task model, different transports.

**Q13. How would you onboard 50 hosts that only have root SSH, then never use root again?**
> A: One bootstrap play as root: create `deploy` user, install `authorized_key` (with `exclusive: true`), drop sudoers file with `validate: visudo -cf %s`. Then inventory sets `ansible_user=deploy`; a hardening play disables root SSH.

**Q14. What's in a production inventory layout?**
> A: `inventories/<env>/hosts.yml` + `group_vars/{all,web,db,…}` + `host_vars/`, one directory per environment; secrets in Vault-encrypted group_vars; dynamic plugins merged via multiple `-i` sources for cloud hosts.

## 🔴 Advanced

**Q15. Design inventory for 3,000 hosts across 4 environments and 3 regions.**
> A: Env dirs + dynamic plugins per cloud account (cached), groups generated by tags (env/tier/region/role) via `keyed_groups`, static entries only for bare metal; ownership metadata from CMDB; per-tier `group_vars` and env-level secret layers; `--list-hosts` + canary groups discipline for blast radius.

**Q16. How do you prevent accidental production runs — at inventory level and platform level?**
> A: Separate inventory dirs and never `all` in prod playbooks; guard vars (a `prod` group requiring `-e confirm=yes` checked by an assert pre-task); canary groups + serial; at platform level, AWX/AAP RBAC + approval workflow nodes; CI requires `--check --diff` artifact before apply.

**Q17. What are the failure modes of inventory caching in dynamic plugins?**
> A: Ghost hosts (deleted instances still listed → connection failures or, worse, actions against recycled IPs), stale groups during autoscale events. Mitigate: tuned `cache_timeout`, `--flush-cache` before critical runs, filters on `instance-state-name`, and a connectivity pre-check play.

**Q18. Explain the semantics of `:&` and `!` pattern composition under `--limit` and inside playbooks.**
> A: They're set operations evaluated over the union of all groups: `:&` intersection, `!` exclusion, `:` union — order matters as written. Same patterns work in `hosts:` and `--limit`; regex needs the `~` prefix.

**Q19. Why do duplicate hosts in multiple groups not duplicate execution?**
> A: Inventory normalizes to a set of unique hostnames; groups are just membership labels. Vars merge by precedence. The one trap: duplicate keys within a single YAML host list silently overwrite (last wins).

**Q20. When would you write a custom inventory plugin?**
> A: When your source of truth isn't covered (internal CMDB, DB, ticketing): subclass `InventoryModule`, parse options, emit host/group data via `inventory.add_host/add_group/set_variable`, support caching — file 14/12 in the course show the pattern and a CMDB example use case.
