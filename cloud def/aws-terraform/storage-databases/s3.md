# Terraform S3 (AWS) — Interview Questions

> **Cloud:** AWS · **IaC Tool:** Terraform · **Levels:** Case A (Basic) · Case B (Advanced/Senior) · Case C (Scenario) · **Reading time:** ~5 min

---

## Case A — Basic

**A1. How do you create an S3 bucket in Terraform?**
**Answer:** `resource "aws_s3_bucket" "b" { bucket = "my-unique-bucket" }`. Names are globally unique across all AWS accounts.

**A2. What is `aws_s3_bucket_public_access_block`?**
**Answer:** A resource that blocks public ACLs/policies at the bucket (or account) level — the modern way to keep buckets private.

**A3. How do you enable versioning?**
**Answer:** `resource "aws_s3_bucket_versioning" "v" { bucket = ... ; versioning_configuration { status = "Enabled" } }`.

**A4. What is a lifecycle rule?**
**Answer:** `aws_s3_bucket_lifecycle_configuration` transitions objects between storage classes (e.g. to IA/Glacier) and expires them on rules.

**A5. How do you set server-side encryption?**
**Answer:** `aws_s3_bucket_server_side_encryption_configuration` with `AES256` (SSE-S3) or `aws:kms` (SSE-KMS) + a KMS key.

**A6. What is a bucket policy in Terraform?**
**Answer:** `aws_s3_bucket_policy` with an IAM-style JSON policy, often generated with `data "aws_iam_policy_document"`.

**A7. How do you upload objects?**
**Answer:** `aws_s3_object` (key, source/bucket, `etag` for change detection) or `aws_s3_bucket_object` (older). For app data, uploads usually happen at runtime, not via Terraform.

**A8. What is `aws_s3_bucket_website_configuration`?**
**Answer:** Enables static website hosting on the bucket (index/error documents).

**A9. What is cross-region replication?**
**Answer:** `aws_s3_bucket_replication_configuration` copies objects to a bucket in another region (with versioning and an IAM role).

**A10. What is an S3 object lock?**
**Answer:** `aws_s3_bucket_object_lock_configuration` enables WORM (write-once-read-many) retention for compliance — must be set at bucket creation.

**A11. What is `aws_s3_bucket_cors_configuration`?**
**Answer:** CORS rules for browser access to the bucket from web apps.

**A12. What is `aws_s3_bucket_acl`?**
**Answer:** The legacy canned ACL resource. With public access block and bucket policies, ACLs are mostly obsolete — prefer policies.

**A13. What is `force_destroy`?**
**Answer:** An argument that lets Terraform delete a bucket even when it contains objects (dangerous — off by default).

**A14. How do you reference an existing bucket?**
**Answer:** `data "aws_s3_bucket" "existing" { bucket = "name" }` or `data "aws_s3_objects"` to list contents.

**A15. What is `aws_s3_bucket_notification`?**
**Answer:** Configures event notifications (to SQS/SNS/Lambda) for object events like `s3:ObjectCreated:*`.

## Case B — Advanced / Senior

**B1. Why are S3 bucket names globally unique and how does that affect multi-account design?**
**Answer:** The name is a global namespace (and part of the URL), so accounts can't share names. Use account/env prefixes (e.g. `prod-org-app-logs`) and consider `bucket_prefix` to let Terraform generate unique names.

**B2. How do you configure encryption with a KMS key end-to-end?**
**Answer:** Create `aws_kms_key` + alias, set `aws_s3_bucket_server_side_encryption_configuration` to `aws:kms` with the key ARN, and grant the bucket/principals `kms:GenerateDataKey`/`Decrypt` via the key policy.

**B3. What is `aws_s3_bucket_accelerate_configuration`?**
**Answer:** Enables S3 Transfer Acceleration (edge-located upload) for faster cross-geography uploads — charges extra.

**B4. How do you replicate existing objects (not just new ones)?**
**Answer:** Replication config with `s3_batch_operations` or enabling "replicate existing objects" (batch) since replication only covers objects created after enabling it.

**B5. What is the S3 backend for Terraform state — how is it related to these resources?**
**Answer:** The state bucket is itself an S3 bucket you typically create (versioned, SSE, blocked public access) — sometimes bootstrapped manually or in a separate stack because it can't manage its own backend.

**B6. How do you set up a private bucket + CloudFront with OAC?**
**Answer:** `aws_s3_bucket` (private), `aws_cloudfront_origin_access_control`, and a bucket policy allowing the OAC principal `s3:GetObject`, plus the distribution origin using the OAC.

**B7. What are `aws_s3_bucket_ownership_controls`?**
**Answer:** Sets object ownership (`BucketOwnerEnforced`) so the bucket owner owns all objects — prerequisite for disabling ACLs and required for some policies/replication setups.

**B8. How do you version and roll back a deleted object?**
**Answer:** With versioning enabled, a "delete" creates a delete marker. Remove the marker (or restore a previous version) — via the console/CLI, or delete the marker key in Terraform/manual ops.

**B9. How do you manage per-environment buckets with modules?**
**Answer:** A bucket module with inputs (name prefix, env, versioning, lifecycle, encryption, replication target) instantiated per environment via `for_each`/tfvars, keeping naming and policies consistent.

**B10. What is the lifecycle configuration gotcha with `filter` and `prefix`?**
**Answer:** Lifecycle rules require a filter (prefix, tag, or empty for all). Wrong filters mean rules silently apply to nothing — test the rule against actual objects.

**B11. How do you handle Terraform drifting when an app uploads objects to the bucket?**
**Answer:** Don't manage app objects with Terraform (only static assets/config via `aws_s3_object`). Keep bucket-level config in Terraform and app data out of it, so plans don't churn.

**B12. What is `aws_s3control_bucket_lifecycle_configuration` vs bucket-level?**
**Answer:** S3 control-plane variants for multi-account/directory buckets; standard buckets use the bucket-level lifecycle resource.

## Case C — Scenario

**C1. A bucket is accidentally public and you must fix it fast.**
**Answer:** Apply `aws_s3_bucket_public_access_block` with all blocks `true` (block public ACLs/policies), remove any public bucket policy/ACL, and enable `BucketOwnerEnforced`. Then add a compliance rule to prevent recurrence.

**C2. You need to delete a bucket Terraform manages but it has thousands of objects.**
**Answer:** Empty the bucket (lifecycle expire rule + wait, or a script), then remove the bucket from config/apply. Enable versioning? Delete all versions and markers too — never use `force_destroy` in prod.

**C3. Objects must be kept for 7 years, then deleted automatically.**
**Answer:** Lifecycle rule: transition to cheaper classes over time, then `expiration` with `days = 2555` (7 years). Optionally object lock for compliance retention. Validate the rule's filter covers all objects.

**C4. You want disaster recovery of the bucket in another region.**
**Answer:** Enable versioning on source and destination, create the destination bucket, add `aws_s3_bucket_replication_configuration` with an IAM role, and (optionally) batch-replicate existing objects.

**C5. Terraform plan shows it wants to recreate the bucket because the name changed.**
**Answer:** Bucket name is immutable — recreation would destroy data. Revert the name change, or if the name must change, create a new bucket and migrate objects/consumers before removing the old one.

**C6. A web app uploads to the bucket from the browser; uploads fail with 403.**
**Answer:** Likely CORS or bucket policy/credentials. Set `aws_s3_bucket_cors_configuration`, grant the right principal (IAM user/role via presigned URLs or identity pool) in the policy, and confirm public access block isn't blocking legitimate access.
